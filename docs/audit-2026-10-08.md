# Project audit

Date: 2026-10-08
POC: Miguel (project owner)
Baseline: v1.7.0, commit 43c3476
TL;DR: Fix swallowed cancellation first, then malformed cache handling and probe process-exit deadlines. Existing suites pass, but they do not cover these failures.

## Scope and verification

Reviewed the Python runner, QML service/setup/account/inventory/clipboard flows, installation and migration scripts, tests and release evidence. No application code changed. No VPN connection, disconnection, shell restart, account registration or privileged cleanup was performed.

- Python 3.14: 193 passed.

- Ruff lint and format checks passed.
- Standalone manifest check and Omarchy manifest validation passed.
- QML lint: 0 project diagnostics, 61 known host metadata warnings.
- Shell syntax and git whitespace checks passed.
- ShellCheck was unavailable.

## Prioritized findings

### 1. P1: cancellation can be swallowed and connection work can continue

Location: `cyberghost_runner.py:1290-1314`, `1564-1615`, `2325-2330`.

`OperationCancelled` inherits `RuntimeError`. Inventory fallback catches it as an ordinary error; key exchange catches it and tries another endpoint. A SIGTERM arriving during either request can therefore fail to stop the operation.

Reproduced with mocks: inventory returned `None` after `OperationCancelled`; key exchange attempted a second host and returned success after the first request raised cancellation. No real connection was made.

Fix: explicitly re-raise cancellation before ordinary fallback catches. Audit all broad exception handlers traversed by lifecycle actions, while retaining activation rollback on cancellation.

Regression tests: cancellation during account-location lookup, country inventory and add-key exchange must propagate, must not try further endpoints and must not reach profile activation.

### 2. P2: structurally malformed cache crashes fallback selection

Location: `cyberghost_runner.py:1051-1078`.

The cache reader checks only that the outer object is a dictionary. `known_servers()` assumes its `countries` value is another dictionary. Valid JSON such as `{"countries":[]}` raises `AttributeError` instead of being ignored.

Reproduced by mocking the cache reader with that structure. This can break server selection when live inventory is unavailable and the local cache is damaged.

Fix: validate the nested schema and treat unusable entries as cache misses.

Regression tests: `countries` as null/list/string/number, malformed country entries and malformed server groups.

### 3. P2: probe budget does not bound runner process exit

Location: `cyberghost_runner.py:1487-1533`.

DNS resolution uses blocking `getaddrinfo()`. `shutdown(wait=False)` lets the function return, but Python waits for running executor workers at interpreter exit. The comment claiming a hard budget does not hold at the process boundary.

Reproduced with a mocked two-second probe: the function returned in 0.02 seconds, while the subprocess exited after 2.18 seconds. Real impact depends on slow or stuck resolver/NSS calls.

Fix: make probing cancellable at the process boundary, or use a resolver with an enforceable deadline. Include DNS in the total budget.

Regression test: measure subprocess exit, not only the function's return time, with a deliberately blocked resolver.

### 4. P2: register and logout are not serialized

Location: `cyberghost_runner.py:893-922`, `2140-2211`, `2390-2420`.

Connect, disconnect and logout take the lifecycle lock; registration does not. A registration already in flight can recreate `native.ini` after logout removes it and reports success.

Established from the lock and write paths; no live concurrent account calls were performed. Normal UI guards reduce the likelihood, but independent runner invocations remain possible.

Fix: serialize account mutation with lifecycle operations and define how logout invalidates pending registrations.

Regression test: pause registration before credential publication, start logout concurrently, then assert a consistent final state.

### 5. P2: relinking can leave an old-account tunnel active

Location: `cyberghost_runner.py:2140-2211`, `1876-1910`; `SetupCard.qml:124-175`.

Registration replaces stored credentials without checking or disconnecting an existing VPN profile. The profile can continue using the old account while the UI reports the newly linked account. This is particularly relevant if credentials are missing or invalid while the tunnel remains active.

Established from source; not reproduced with real accounts.

Fix: reject account changes while connected, or explicitly disconnect and serialize the transition. Distinguish same-account session refresh if that is intended to remain supported.

Regression test: relink with an active profile, including missing-current-credentials recovery.

### 6. P2: successful update can leave the running UI stale

Location: `README.md:56-63`, `docs/visual-testing.md:20-22`; installed Omarchy updater's rescan behavior.

The user's post-update screenshot displayed obsolete WireGuard/resolvconf setup text while installed 1.7.0 readiness checks passed. Current code does not contain that text. The visual-testing guide already warns that imported QML may remain cached after rescan.

The installed updater issues a plugin rescan, which does not guarantee replacement of loaded QML. The README's “Updates need no extra step” is therefore misleading on this host.

Fix: document the supported shell restart after updates when the UI remains stale, and pursue a proper reload mechanism with Omarchy. Do not automatically restart the entire shell without making that interruption clear.

Regression/integration check: update a running 1.6.x instance and verify that rendered setup text and backend readiness both reflect 1.7.0.

### 7. P3: concurrent cache writers can lose country entries

Location: `cyberghost_runner.py:1081-1098`, `1313`, `1373-1381`, `1417`.

Cache updates perform unlocked read-modify-replace. Atomic rename prevents partial JSON but not lost updates. Sync and foreground lookup can read the same old snapshot and replace each other's country additions. The sync lock excludes another sync, not every cache writer.

Established from source; no deterministic two-writer reproduction performed.

Fix: use a common lock around cache read-modify-write, or separate country files.

Regression test: synchronize two writers at the read boundary and verify both countries survive. Also remove temporary `.servers_*` files after write/replace failures.

### 8. P2 for developer reset: fixed-name system files are deleted without recognition checks

Location: `fresh-install.sh:127-135`; compare `scripts/remove-legacy-helper.sh:45-70`.

The destructive reset unconditionally deletes the helper, rule and WireGuard configuration. The normal migration remover checks helper identity and preserves customized rules. Reset can delete customized or repurposed files at those names.

The reset has explicit confirmation and is developer-oriented; this is not the ordinary upgrade path.

Fix: share recognized-file cleanup logic, or back up customized files and require a separate explicit purge decision. Avoid removing the installed plugin before privileged cleanup has succeeded.

Regression tests: customized rule, unrecognized helper and cleanup authorization failure.

### 9. P3: native error messages recommend an optional vendor CLI

Location: `cyberghost_runner.py:1595-1613`.

Authentication failure recommends `cyberghostvpn --setup`; TLS failure recommends installing/configuring that CLI. The supported native setup does not require it, so these instructions can send users down the wrong recovery path.

Fix: prefer native account relinking and actionable certificate/network diagnostics. Describe vendor inventory only as an optional fallback.

Regression tests: authentication and TLS error text agrees with the native setup flow.

## Integration work still required

These are verification gaps, not confirmed bugs:

- DHCP-mode VPN DNS routing, explicitly unchecked in `docs/release-checklist.md:18`.
- Live 1.6.x tunnel migration and helper cleanup, unchecked at line 19.
- Multi-monitor ownership election, hotplug and concurrent commands.
- Real activation timeout/cancellation and residual profile/routes/DNS cleanup.
- Clean install, running-shell update, disable/re-enable and removal.
- Current final-commit CI evidence. The local checklist leaves this unchecked; remote CI was not inspected in this audit.

The project explicitly does not provide a kill switch. That documented scope limitation is not classified as a regression.

## Suggested order

1. Cancellation propagation, with tests at all fallback boundaries.
2. Cache schema handling and bounded process exit.
3. Account mutation serialization and connected-account transitions.
4. Upgrade/reload guidance and integration coverage.
5. Cache writer locking, reset safeguards and native recovery messages.
6. Close outstanding live DNS, migration and multi-monitor checks.

This audit does not prove the absence of other bugs. Network and compositor behavior were reviewed through code, existing evidence and automated tests rather than destructive live scenarios.
